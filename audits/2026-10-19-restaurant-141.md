# Restaurant application assessment — 19 October 2026

## Confirmed causes and repairs

- The v140 login remained disabled while 11 scripts downloaded sequentially. Replaced that chain with one compiled core asset. The inline entry accepts a Sign in or Forgot password click immediately and forwards it once startup is ready; it never sends credentials before the authentication handler is installed.
- The previous service worker aborted uncached requests after four seconds. New releases use new URLs, making them especially vulnerable. Release 141 activates its worker without a blocking precache and removes that short network deadline. It retries a failed core/style download once after worker replacement, names failed files, and preserves older caches and all private IndexedDB queues.
- Seventeen external stylesheets included overlapping login rules. Early styles supplied a green logo tile; later styles replaced it. The compiled workspace stylesheet excludes login selectors. One inline stylesheet controls the login from first paint, using measured Accounting desktop values: 430px width, 426px normal height, 28px padding, transparent logo tile, 36px desktop inputs. Responsive controls retain touch sizing.
- Lazy module downloads had no deadline. They now share in-flight downloads, identify failed assets, allow retries after network errors, and avoid injecting a second copy after an uncertain timeout. Related source files are compiled into Inventory, POS and Settings bundles.
- Kitchen preparation/waste history used unpaginated reads. It now loads every page, rejects partial results, checks session/navigation ownership and bounds each read. Inventory reads also have a recoverable deadline.
- Sign-out now cancels outstanding catalog/Kitchen reads and invalidates shared hydration, preventing a stale in-flight login from being reused.

## Assessment coverage

Live read-only browser inspection covered the Restaurant login, reload behavior, runtime errors and the Accounting login reference. The Restaurant Supabase project reported ACTIVE_HEALTHY; installed migration names matched the repository's feature history.

Isolated JavaScript and PostgreSQL-compatible fixtures cover authentication failure paths; module access and permissions; inventory movement pagination; POS pricing, payment, refund and stock linkage; receipt reports and CSV escaping; recipe nesting, conversions, batch factors, labor/surcharge costing and wastage; public-menu publishing; and session ownership. They do not write test transactions into the live database.

All 32 non-browser test suites passed after the repairs. JavaScript bundle syntax, generated asset checks, and deterministic-build checks passed.

A stale regression still expected the removed decorative banner. It was updated to assert the user's required banner-free header instead. Legacy bootstrap tests remain historical coverage; startup141 and module-loader141 exercise the current entry architecture.

## Remaining limits and advisories

An authenticated end-to-end session with the user's real account has not been exercised. Fixture results do not prove that every workflow works with every production record or on every device.

Read-only Supabase advisors reported existing items, none explaining the client-side file-download failure:

- 16 intentionally exposed SECURITY DEFINER helpers/RPCs. Existing server-side permission tests pass; these require preserving their internal access checks, not blindly revoking RPC access. [Supabase guidance](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
- Leaked-password protection is disabled. This is an account security setting, not changed by this release. [Password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- Performance advisories include 12 uncovered foreign keys, a per-row membership policy auth check, overlapping permissive policies and unused indexes. These are follow-up optimization candidates, not established causes of the reported login outage. [Index guidance](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [policy guidance](https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan).
