# Restaurant login correction — release 142

The reported `workspace stylesheet took too long to download` error was still possible in release 141. Authentication waited on a separate asynchronous stylesheet readiness promise, then waited for module downloads, records and branding before hiding login. A stylesheet load event missed before the listener was attached could also leave that promise unresolved. These are distinct from internet connectivity or invalid credentials.

Release 142 embeds the compiled workspace stylesheet in both entry documents. There is no shell CSS download promise, timeout or retry in startup. The login CSS remains the exact existing release 141 source, preserving its Accounting-sized form and transparent logo background.

After authentication and active Restaurant access verification, login closes and the workspace appears immediately. Module code and records open through the existing module router, with its local loading and error handling. Optional branding loads in the background. Module/record failures do not clear the verified session or reopen login. Required password changes still finish before entry. Verification requests have a 15-second deadline; this deadline does not cover user password-entry time.

The extra `Opening secure sign-in` message and fullscreen sign-in/checking/workspace progress screen are removed from the login path. Controls still prevent duplicate submissions while the request is pending, and display actual authentication failures.

A new versioned core, module URLs and service worker prevent existing caches from serving the previous startup. No database, permissions, transactions, offline queues or Accounting changes.

## Validation

64 checks passed across 9 targeted suites: startup141 (now tests release142), login140, mobile-login132, module-loader141, worker-runtime128, integration-ui133, access-runtime128, home-report139 and boot139. The new verification tests hold module and branding requests indefinitely, reject module loading, time out verification, sign out during verification/loading, reject inactive/unassigned accounts, and require password changes. Verified entry does not wait on the held requests. Compiled JavaScript parses.

These use deterministic fixtures, not a real user's account. Live unauthenticated browser checks are separate; successful real-account sign-in has not been established in this environment.
